# Codex request usage proof (inactive)

This local proof is not advertised or used for Teams execution. It has no provider calls or cost estimate. The old all-history v1 token counter and its source binding retain their existing meaning. A `codex_request_usage` child is a keyed profile identity attached to the same Codex thread identity; it is not a new owner and does not claim the old numeric profile is available.

When a library explicitly requests Teams source proof, the Codex indexer can certify a bounded request sequence from an independent, header-identified native rollout. It requires a complete UTF-8 JSONL prefix, unique unambiguous native request identities, explicit RFC3339 request times, explicit model context, exact non-negative JavaScript-safe integer input/output/total counters and a cumulative thread total that reconciles every request and duplicate checkpoint. Conflicting model/effort assertions, gaps, inherited or forked history, unsupported usage shapes, missing timing or model evidence, contradictory snapshots and excessive source size/count are withheld. An exact repeated request is counted once. Cache and reasoning counts remain explicitly unknown if absent; no zero or price is inferred.

The proof digest covers the canonical ordered private local fact sequence, including a domain-separated request-ID digest, time, model, effort and known/unknown counters. Its child token, witness and evidence revision use separate keyed domains and one thread dependency; no per-request value, native identity, source record or path belongs in the Teams profile wire. A locally stored proof is not ownership, source protection, a complete inventory, a current server assignment or send authority.

Each captured request's indexed accounting message, time and model must match its native observation, and its indexed request ledger must independently match the complete per-hour/model/effort counters. Both representations and the proof commit in the same index transaction. A source rewrite or a relevant message, session or ledger change removes the prior proof. Opted-in libraries revisit existing Codex sources once after upgrade. Future readers must still check current source custody, mapping, indexed digest, library instance, source and privacy revisions, and current accepted server anchor. Typed use stays fail-closed until verified server assignments, effective protection and reviewed recovery generations are integrated. Project witnesses and price-book/rounding parity are separate proof and execution work; a missing price remains unknown.
