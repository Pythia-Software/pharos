# Homepage query card implementation tracker

The homepage uses existing URL bookmarks and Query Table 0.5.0. It ships 22 executable recipes across 20 catalog ideas. All 96 original concepts remain below, with their richer requested behavior and blockers preserved. “Partial implementation” means the current card answers a narrower observed question; it does not claim to deliver the complete original concept.

Recommendations require matching results in explicit 1, 7, 30 or 90 day windows. Windows include today and the preceding local calendar days so daily Usage facts remain whole. The card editor can change these rolling windows; existing fixed ranges remain intact until explicitly changed. Empty saved views stay in the collection. Titles, descriptions and ordering use `pharos-bookmarks-v1`; old Query Table saved-query IDs are preserved during migration. Category eyebrows and cover colors share the subject palette in `web/src/query-categories.ts` across saved and suggested cards; named chart series retain the shared Usage palette.

The machine-readable companion [homepage-query-cards.json](homepage-query-cards.json) retains every original recipe, eligibility rule, proposed preview, implementation mapping and capability request. Update both files when a deferred card is implemented.

## Integration stages

1. Current implementation: homepage, canonical bookmark collection, rolling URL bridge, live eligibility checks, shared chart marks and colors, and the 22 recipes above.
2. After metric-creation-playground lands: adopt the released package with a conformant SQLite/map executor before enabling formula metrics, distributions and richer measures.
3. After later capabilities land: implement derived message, episode, interval and lineage datasets in Pharos; revisit the corresponding catalog rows individually.

Preview requests are limited to three concurrent executions, have a 15-second deadline and are cached for one minute. The conveyor starts with one ready card in a fixed middle slot, then reveals ready pairs on either side; graph-only x-rays appear as that belt grows beyond the reading area. A final unpaired result waits until loading finishes before joining the outer end. Clicking a side x-ray slides its card into the middle. They use all-matching aggregations, never sums over the visible table page. SQL aggregate group caps and map-backed datasets still limit execution; the initial homepage has no real-archive latency benchmark. Source freshness and exact-versus-estimated provenance remain host responsibilities.
