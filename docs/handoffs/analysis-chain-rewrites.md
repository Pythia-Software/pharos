# Handoff: stop the analysis chain rewriting what has not changed

**Completed** in #288 (no-op rewrites), #289 (authorship diff store) and
#290 (incremental authorship). Kept as the record of the request.

## Assignment

A manual **Index changes** takes 8–13 minutes, about 95% of it in the
library-wide analysis chain. Two defects in that chain cause most of the cost:

1. **The identities stage rewrites unchanged rows.** It rewrites about 3,500
   Conductor conversations with the values they already hold. Unguarded
   triggers then mark each of their workspaces dirty, so after every chain the
   Search view recomputes about 4,000 workspaces (nearly the whole library),
   which takes up to 28 minutes.
2. **Writing classification (`analysis.authorship`, "Classify your writing")
   rebuilds from scratch every time.** It reclassifies the whole library and
   deletes and reinserts every row in one unchunked write transaction. Any
   new message triggers this, and it takes 214–609 s (average 358 s).

Fix both, without changing any classification or Search view output.
Ship three stacked PRs, in this order:

| PR | Change | Size |
|---|---|---|
| 1 | Identities stops rewriting unchanged conversations; the chain marks nothing dirty when nothing changed | S |
| 2 | Authorship writes only the rows that differ, in chunks, and no long-lived read snapshot | S |
| 3 | Authorship reclassifies only what new data can affect, with a full-rebuild fallback | M–L |

This is groundwork for running the chain automatically after scheduled
indexes. **Do not change when anything runs.**
- Scheduled indexing still defers the chain (`sync_deferred`).
- The chain still runs only after a manual index.
- The scheduling change is a later, separate piece of work.

## Part 1 (PR 1): the Search view refresh

### Cause (verified)

**The unguarded update.** `ReconcileIdentitiesContext` (`ingest.go:2083`)
calls `inheritHarnessAliasesContext` (`ingest.go:2122`) on every run.
`inheritHarnessAliasesTxContext` (`harness_version.go:289`) runs:

```sql
UPDATE conversations AS wrapper SET harness_version_first=COALESCE(…), harness_version_last=…, harness_version_source='alias'
FROM (… native-alias peers …) peer
WHERE wrapper.id=peer.wrapper_id AND wrapper.harness='conductor'
```

There is no "only if it differs" condition. On the backup it matches 3,538
conversations in 3,536 workspaces, and 3,532 of them already hold
`harness_version_source='alias'` with the same versions. Its other caller is
`library_upgrade.go:368`.

**Three triggers on `conversations` fire on every UPDATE**, even when no
column changes:
- **`workspace_library_conversations_update`:** generated by
  `libraryTriggerDDL` (`library.go:136`) with no `WHEN` clause. It marks
  `workspace_library_dirty` for the OLD and NEW workspace, and that dirty set
  drives `maintainLibrary`'s Search view refresh.
- **`analysis_conversations_UPDATE`** (`analysis_partitions.go:~100`): writes
  a fresh random revision to `finding_message_revisions`, which invalidates
  findings' per-conversation cache.
- **The `mcp_metric_dirty` triggers** (`mcp_metric_projection.go:~62`): mark
  the workspace for the MCP metric projection. The backup has 11,630 rows
  pending there.

`origin.go:83` shows the pattern to follow: its trigger has
`WHEN OLD.x IS NOT NEW.x OR …`.

**The `'null'` aliases.** `ingest.go:1407` stores
`jsonText(value.Aliases)`. `jsonText` (`util.go:121`) marshals a nil slice as
`null`, so 28,009 conversations hold `aliases_json='null'`.
`reconcileIdentities` selects `WHERE aliases_json<>'[]'` (`ingest.go:2099`),
which picks all of them, and runs one `writeTransaction` per conversation
that does nothing. The `catalog.go:398` and `:471` readers already tolerate
`null`.

**Writes to check in the same stage:**
- **`UPDATE workspaces SET activity_at=…`** (`ingest.go:2149`): it runs outside
  `writeTransaction`, so it bypasses the writer gate.
- **`refreshWorkspaceNames(tx, nil)`** over every workspace (`ingest.go:2156`).

For each, verify that it writes only on a real change. Then do the same for
every other chain stage: github (`RefreshRepositoryForgeIDs`), git
(`refreshMainIntegrations`), tools (`ensureToolRollup`) and findings.

### What to change

**Already done.** Steps 1 and 2 shipped with background updates, because
the identities stage now runs after every scheduled index: the guarded
`UPDATE` (`harness_version.go`) and the `'null'` filter (`ingest.go`), with
`TestHarnessBackfillAndAlias` checking that a second inherit marks nothing
dirty. Start from a `master` that includes them; the rest of PR 1 (the
`WHEN` decision, the audit of other writers, the whole-chain invariant test)
remains.

1. **Guard the harness update.** Make `inheritHarnessAliasesTxContext` update
   only rows whose `harness_version_first`, `harness_version_last` or
   `harness_version_source` would actually change (`IS NOT` on each).
2. **Stop the per-conversation alias transactions.**
   - Treat `null` like `[]` in the `reconcileIdentities` filter.
   - Write `[]` for new rows, by normalizing at the source or in `jsonText`'s
     caller; don't change `jsonText` globally without checking its other
     callers.
   - If you migrate the existing `null` rows, remember that the migration
     itself fires the unguarded triggers. Do it after, or together with,
     step 3, or not at all: the filter alone removes the cost.
3. **Decide on `WHEN` clauses for the three trigger families**, as
   belt-and-braces against future no-op updates.
   - `libraryVersion()` hashes the trigger DDL (`library.go:168-177`), so
     changing those triggers forces **one full Search view rebuild** on each
     library's next open. The other two families are created with
     `IF NOT EXISTS`, so they also need a migration path.
   - Measure that one-time cost on a fixture, and state it in the PR.
   - If it is not worth it now, guarding the writers is enough. Say which you
     chose and why.
4. **Fix the other writers you find** in your audit that write without a
   change.

### Tests (Go, `internal/archive`)

- **The invariant that matters.** Seed a small catalog that includes a

  - no row of `conversations` was updated. Use `total_changes()` or a

- **Keep the existing harness-version tests green.** A first run must still

## Part 2 (PR 2 and PR 3): writing classification

`docs/human-authorship.md` describes the rules. This is a performance change
with output parity. **Do not change classification results.** Leave
`authorshipVersion` (`authorship.go:28`, `authorship-v8`) alone, unless
stored state changes shape in a way that needs a rebuild.

### How it works today (verified in code; the time split is inferred)

**The flow.** `RebuildAuthorship` (`authorship.go:1323`) runs:
- **`authorshipInputs`** (`:1355`/`:1361`): reads
  - every workspace, the identity and Conductor links;
  - `deriveLaunches` (`launches.go:246`): every conversation and every
    `claude`/`agy`/`codex` command, with one candidate query per stream of
    headless runs;
  - every user message's full text, sorted in memory.
- **`classifyInputs`** (`:1481`): streams every assistant message and
  command, edit and MCP tool call since the first user message minus 7 days,
  which is the whole history. `classifyInputsFrom` keeps that read statement
  open for the whole loop (`:1491-1545`), pinning a read snapshot for
  minutes.
- **`storeAuthorship`** (`:1549`): in **one transaction** it does
  - `DELETE` of all of `conversation_launches`, `message_authorship` and
    `message_authorship_spans`, then reinserts every row;
  - `cacheAuthoredWorkspaceNames` (`workspace_names.go:338`), which clears
    `authored_*` on every `workspace_names` row and runs
    `refreshWorkspaceNames(tx, nil)`.

**Triggers fire for every row** (see `assets/schema.sql`):
- **`human_query_text_insert`/`_delete`** (`:1387-1395`): re-index each
  message's full text into the trigram `human_query_text` index, about 500 MB
  per rebuild.
- **`text_search_message_authorship_spans_*_v2`** (`:1278-1288`): update
  `meta` once per span.
- **The `query_cache_*` triggers** (`query_cache_generation.go`): fire on all
  four tables.
- **The `origin_dirty_*` triggers on `conversation_launches`** (`origin.go:69`):
  force a full `computeOrigins` pass.

Because these triggers exist, `DELETE FROM` cannot use SQLite's truncate
optimization and deletes row by row.

**Invalidation is global.** A rebuild is due when
`tool_ledger_generation:authorship_inputs_generation/authorship-v8` differs
from what was built (`authorship.go:1149-1160`). Ingest moves
`tool_ledger_generation` (`tool_ledger_store.go:303`), and
`invalidateWorkspaceAuthorship` (`workspace_names.go:94-113`) moves the other.
So one new message in one conversation forces the full rebuild.

**Keep this invariant from #96:** messages containing only user text must
invalidate writing classification independently of tool activity.

**Who starts it:**
- **The chain's `authorship` stage** (`incremental_recovery.go:432-463`).
- **Explicit source sync** (`api.go:1054`) and **recovery**
  (`incremental_recovery.go:579`).
- **`ingestEnded`** (`authorship.go:1249`): the follow-up after an ingest.
- **Reads, through `ensureAuthorship`** (`:1194`). They rebuild only when the
  ledger is missing or from older rules; otherwise they serve the stored rows
  and report them stale.

### PR 2: write only the difference, in bounded pieces

1. **Write only the difference.** Compute the new results as today, but
   compare them against the stored `message_authorship`, spans, launches and
   `workspace_names.authored_*`. Then `INSERT`/`UPDATE`/`DELETE` only the
   rows that differ. No whole-table `DELETE`. An unchanged message must not
   touch `message_authorship`, so its trigram entry is not rewritten.
2. **Commit in chunks** of a few hundred rows or a time budget, under
   `writeTransaction`. Record the built generation only after the last chunk.
   - Readers in between see a mix of old and new rows for a short while;
     that is acceptable.
   - A stop or crash mid-way must leave the generation unrecorded, so the
     next run redoes it, and the diff makes that cheap.
3. **No snapshot pinned for minutes.** Read the assistant and tool-call stream
   in bounded windows, for example by `rowid` or time ranges, each its own
   statement.
4. **Add per-phase timing** (inputs, classify, store, plus rows written per
   table) to the operation's progress or detail, so the journal shows where
   the time goes.

**Expectation:** a rebuild after a small ingest writes tens of rows, not
100k. Classification is still a full pass (minutes), which is PR 3's job.

### PR 3: reclassify only what changed

**Cross-conversation dependencies** (verified in code):

| Input | Reach | Bounded? |
|---|---|---|
| Templates: text seen in ≥ 5 sessions on ≥ 3 days (`authorship.go:610-631`) | Counted over all messages, later ones included | No: a new message can make earlier messages templates |
| Re-sent text, `userText` (`:722`) | Every earlier user message, of any age | Only affects later messages |
| Reused lines, `lines` (`:784`) | Every earlier user message | Only affects later messages |
| Copied agent output, `agentText` | 7 days of agent text, across all conversations | Yes |
| Launch links; sub-agent and launch folding (`foldedParents`, `writing_table.go:245`); mirrors; Conductor claims | Graph-wide | Yes, but a change in a conversation's automated status changes what enters `userText` (`:641-648`) |
| Typing speed, question forms | Within the conversation | Yes |

**A design to start from** (validate it, don't assume it):

**Persist the state** the full pass rebuilds in memory, so earlier messages
needn't be re-read:
- **Re-sent text:** candidate hash → message and offset. Verify by re-reading
  the source text, and keep linking to the *latest* earlier copy, as today.
- **Reused lines:** line key → first origin plus up to 3 conversations.
- **Templates:** template key → sessions and days, plus a `template_key` on
  `message_authorship`.

**Track the earliest affected time `W`** with a trigger-fed dirty set
recording the earliest `sent_at` of any user message, assistant message or
tool call written since the last build. That replaces "the generation moved,
so rebuild everything".

**Each run:**
- reclassify user messages with `sent_at >= W`, loading agent text for
  `[W − 7 days, now]`;
- re-derive launches only for streams touching new runs or commands;
- when a template key crosses its threshold, reclassify every message
  carrying that key;
- when automated status or folding changes for a conversation, move `W` back
  to that conversation's first message.

**Fall back to the full pass** (PR 2's diffing store) when:
- the rules version changes;
- identity links or mirrors change;
- a backfill moves `W` far into the past, or the suffix exceeds a cap; make
  the cap a package variable tests can lower.

**Parity test (required).** Build a fixture covering:
- templates crossing the threshold;
- re-sent text and reused lines;
- copied agent output at the edge of the 7-day window;
- launches and folding.

Ingest it in several random splits, running the incremental path after each.
Assert the stored results equal one full rebuild over everything. Use a
seeded random split, plus a few hand-picked adversarial ones, such as the
template-creating message arriving last. This is the test that justifies the
whole change. It compares against the real full path, not a second copy of
the algorithm.

**Stop and report** rather than ship if parity cannot be reached for some
dependency. Say which one, and leave that case on the full-pass fallback.

### Measuring

- **Before/after on identical input.** Write a probe (`-tags probe`; see the
  existing probes' headers) that runs `authorshipInputs` + `classifyInputs`
  read-only against the immutable backup, and reports:
  - phase timings;
  - how many rows the diffing store *would* write against the stored rows,
    which should be close to zero;
  - for PR 3, how many messages it reclassifies for a `W` of one hour ago.
- **The end-to-end number** comes from the journal once a build with the fix
  runs on the production library (`analysis.authorship` durations). Report
  what you measured and its limits. Don't extrapolate from a fixture to the
  production library.

## Done when

- **PR 1:**
  - The chain over an unchanged catalog updates no conversation rows and
    marks nothing in `workspace_library_dirty`, `mcp_metric_dirty` or
    `finding_message_revisions` (the invariant test).
  - Identities runs in well under a second on that fixture.
  - The PR states the trigger `WHEN` decision and its one-time cost.
- **PR 2:**
  - A rebuild with no new data writes zero rows to the authorship tables and
    `workspace_names`.
  - Writes are chunked, and no read statement stays open for the whole
    classification.
  - Per-phase timings are visible on the operation.
- **PR 3:**
  - The parity test passes.
  - A small change reclassifies only messages from `W` onward.
  - The fallbacks are tested.
  - On the probe, the incremental path's cost is proportional to the change.
- **Every PR:**
  - `go test ./...`, `npm --prefix web run check` and
    `npm --prefix web run test:full` pass.
  - `docs/human-authorship.md` and `docs/background-work.md` §5 are updated
    where the behaviour they describe changed.
