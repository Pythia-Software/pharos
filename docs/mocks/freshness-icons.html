The database-clock direction, refined: a filled pie shows hours behind, and a checkmark replaces the clock when up to date. Try it at 15px, in the header, and without color.

The database clock, refined

One full dial = 12 hours behind, filling clockwise from the top. It stays full at 12h+; the text keeps the exact age. The checkmark means up to date. These are enlarged drawings; actual UI sizes appear below.

Reference: the original PR’s FreshnessIcon geometry, preserved before the database-clock implementation, including its 20 × 20 viewBox. The working tree now uses the approved database clock. The five alternatives use the repo’s 24 × 24 grid. These are code-rendered, synthetic UI examples; no photographic reference was used.

What I’d look for

  • A clock-shaped quantity. Three hours is a quarter, six is a half, nine is three quarters. The dial never wraps back to empty.
  • A calm current state. The checkmark replaces the entire clock face; the database outline stays recognizable.
  • Legibility at 15px. The clock hands are removed so the small face can show a clean area of fill.
  • Freshness stays separate from work. The pie measures lag, not processing progress. Running and paused jobs can have the same stale data.
  • Keep exact age in text. A full dial means 12h or more. Unknown status never gets a checkmark or an invented slice.
Drawing rules and selected SVG

Original geometry; 24 × 24 viewBox; 1.6-unit currentColor outline; round caps and joins; no gradients, font glyphs, or icon packages. The pie is intentionally filled to encode a quantity, using the icon standard’s meaningful-solid-mark exception. The database and checkmark remain unfilled. Existing history and info symbols are reused. The PR baseline and earlier database-clock reference are preserved.

The database direction keeps an unfilled question badge for unknown status and an unfilled dash badge for missing results. Other clock/history alternatives reuse the existing info symbol for unknown status.

Production integration would add symbols to the page shell and their names to IconName, following docs/iconography.md.
